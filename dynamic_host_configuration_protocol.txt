STEP 1 - CONFIGURE R1 AS DHCP SERVER

---------------- R1 ----------------

Command                                          Explanation
-----------------------------------------------------------------------------------------

configure terminal                               Enter Global Configuration mode.

ip dhcp pool POOL10                              Create/enter DHCP pool "POOL10".
 network 10.0.0.0 255.255.255.0                  Define the scope of addresses to hand out.
 default-router 10.0.0.1                         Set the default gateway given to clients.
 dns-server 10.0.0.1                             Set the DNS server given to clients

                                                  lab — command shown for demonstration).
exit                                             Return to Global Configuration mode.

ip dhcp excluded-address 10.0.0.1 10.0.0.10      Reserve .1-.10 in this pool so DHCP never
                                                  hands them out (configured in global
                                                  config mode, not inside the pool).

ip dhcp pool POOL20                              Create/enter DHCP pool "POOL20".

CONCEPTS LEARNED
==================================================

• DHCP (Dynamic Host Configuration Protocol) — a protocol that
  automatically assigns an IP address, subnet mask, default gateway, and
  other network settings (like a DNS server) to a client, so a host
  doesn't need to be configured with this information by hand.
• APIPA (Automatic Private IP Addressing) — a fallback address a Windows
  host self-assigns from the 169.254.0.0/16 range when it's configured
  for DHCP but receives no response from any DHCP server; it signals
  "no DHCP reply reached me," not a normal working address.
• DHCP pool configuration (`ip dhcp pool`, `network`, `default-router`,
  `dns-server`) — the set of commands that define a DHCP server's scope
  of addresses to lease (`network`), the default gateway to hand out
  (`default-router`), and the DNS server to hand out (`dns-server`), all
  entered inside a named DHCP pool.
• Excluded address ranges (`ip dhcp excluded-address`) — a command that
  reserves specific addresses within a pool's scope so DHCP never leases
  them out (e.g. addresses already hand-assigned to a gateway or server);
  configured in global configuration mode, not inside the pool itself.
• DHCP client interface configuration (`ip address dhcp`) — an interface
  command that tells a router (or switch SVI) to obtain its own IP
  address dynamically from a DHCP server, the same way a PC would.
• DHCP relay agent (`ip helper-address`) — an interface command that
  converts DHCP's broadcast-based Discover/Request messages into a
  unicast forwarded to a specific DHCP server, allowing a subnet with no
  local DHCP server to still obtain addresses from one elsewhere, since
  broadcasts don't cross a router hop on their own.
• Rule of thumb: configure the relay agent (`ip helper-address`) on the
  router interface closest to the hosts needing an address, not on the
  DHCP server's own router interface.

==================================================
STUDY NOTES, EXAM SCENARIOS & REAL-WORLD CONTEXT
==================================================

DHCP request cycle (DORA)
  Discover -> Offer -> Request -> Acknowledge. `ipconfig /release` +
  `/renew` in this lab just triggers this cycle manually. Both Discover
  and Request are broadcasts — that's why the exchange can't cross a
  router without a relay agent (below).
  Exam: if asked why a client re-broadcasts DHCPREQUEST instead of
  unicasting to the offering server — it lets any other DHCP server on
  the segment see the offer was accepted/declined.
  Real world: a host stuck "obtaining IP address" is usually failing
  somewhere in this cycle — packet capture on the switchport shows which
  step never got a reply.

APIPA (169.254.0.0/16)
  A host lands here only when set for DHCP and getting no response at all.
  Exam: know the range (169.254.0.0/16) and that it means no DHCP reply
  reached the client — not a misconfigured static IP.
  Real world: 169.254.x.x is the fastest visual sign a request never
  reached a server — check the physical link/VLAN and the segment's relay
  config before suspecting the pool itself.

Excluded addresses
  Configured globally (`ip dhcp excluded-address`), not inside the pool.
  Exam: a classic trap, since every other pool setting lives inside
  `ip dhcp pool` — expect a question testing whether you know this one
  command lives outside it.
  Real world: this range protects addresses you've already hand-assigned
  (gateway, DNS servers, printers, APs) from being leased out again.

DHCP relay agent (`ip helper-address`)
  DHCP broadcasts die at the first router hop, so a central server can't
  directly serve a subnet it isn't attached to; `ip helper-address` on
  that subnet's gateway interface converts the broadcast to a unicast at
  the real server.
  Exam: know it's configured on the router interface *closest to the
  clients*, not on the DHCP server's own router — and that it forwards
  several well-known broadcast services, not only DHCP.
  Real world: this is how one central DHCP server (or redundant pair)
  covers every branch/VLAN in an enterprise network without a local server
  per site. If one subnet's hosts get APIPA while others don't, checking
  that subnet's gateway for a correct `ip helper-address` is one of the
  first troubleshooting steps, before touching the pool.

DHCP client on a router interface (`ip address dhcp`)
  Same mechanism as a PC requesting an address, just on a router port.
  Real world: this is how a small-office/branch router's WAN-facing
  interface leases its public IP from an ISP.
