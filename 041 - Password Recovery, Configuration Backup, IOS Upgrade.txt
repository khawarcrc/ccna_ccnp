==================================================
LAB NAME
==================================================

Lab 041 - Password Recovery, Configuration Backup, IOS Upgrade

==================================================
LAB OBJECTIVE
==================================================

Perform three separate but commonly-paired device management tasks on
R1: recover access after being locked out by a forgotten enable
password (using ROMMON and the configuration register), back up R1's
startup configuration to a TFTP server, and upgrade R1's IOS image to a
newer version stored on that same TFTP server.

==================================================
TOPOLOGY
==================================================

  +----------+                      +----------------------+
  |   R1     |----- G0/0 -----------|      (LAN segment)    |
  +----------+                      +-----------+-----------+
  (console access                               |
   used throughout                        +-----------+
   for ROMMON recovery)                   | TFTP1     |  192.168.1.100
                                           +-----------+
                                     (holds R1's backed-up config
                                      and the newer IOS image)

R1 is accessed directly (console) throughout this lab, including while
in ROMMON during password recovery — this is not a remote-access
scenario. TFTP1 (192.168.1.100) sits on R1's LAN, reachable via R1's
G0/0 interface, and serves two purposes in this lab: destination for
the backed-up startup-config, and source of the newer IOS image used
in the upgrade.

                                          (`no shutdown`) after being found down

==================================================
STEP 1 - PASSWORD RECOVERY VIA ROMMON
==================================================

Scenario: R1 is locked out — someone configured an enable password and
it has been forgotten, so Privileged EXEC (and therefore Global
Configuration) mode cannot be reached to change it.

---------------- R1 (physical power cycle, then ROMMON) ----------------

Action                                            Explanation
-----------------------------------------------------------------------------------------
Power off, then power on R1                       In Packet Tracer: click R1 -> Physical
                                                   tab -> toggle the power switch off
                                                   then on, to restart the boot process.
Press Ctrl+Break (in the CLI) before boot          Interrupts the boot process before IOS
completes                                          finishes loading, dropping the device
                                                   into ROMMON (ROM Monitor) mode — a
                                                   minimal, password-independent
                                                   pre-boot command environment.

---------------- R1 (in ROMMON) ----------------

Command             Explanation
-----------------------------------------------------------------------------------------
confreg 0x2142      Changes the configuration register to 0x2142, whose low-order
                    bit combination tells the router, on its next boot, to skip
                    (ignore) the startup-config in NVRAM and boot with a blank
                    default configuration instead — this is what allows entry to
                    Privileged EXEC mode without any password, since no
                    passwords exist in a default/blank configuration.
reset               Reboots the router, which now boots ignoring NVRAM's
                    startup-config, coming up with a blank running-config (and,
                    as a side effect, its default hostname "Router" reverting —
                    though this changes back to "R1" once the real startup-config
                    is copied in during the next step).

---------------- R1 (back in normal CLI, blank config) ----------------

Command                       Explanation
-----------------------------------------------------------------------------------------
enable                        Enters Privileged EXEC mode — no password prompt,
                              since the device booted with a blank configuration.
copy start run                Copies the startup-config (still intact in NVRAM,
                              untouched by the config-register change) into the
                              running-config, making the original configuration
                              (hostname, interfaces, etc. — but not yet the old
                              enable password, since that will be overwritten
                              next) active again.
configure terminal
enable secret CCNA             Sets a new, known enable secret, replacing the
                              forgotten one now that Privileged EXEC access has
                              been regained via the blank-config workaround.
interface GigabitEthernet0/0
no shutdown                   Also re-enables R1's G0/0 interface (needed later
                              in the lab to reach TFTP1), since it was found shut
                              down.
exit
config-register 0x2102        Restores the configuration register to its
                              standard default value (0x2102) — the equivalent
                              command from the regular CLI (as opposed to
                              ROMMON's `confreg`) is `config-register`. This step
                              is important: leaving the register set to ignore
                              NVRAM would make R1 discard its startup-config on
                              every future boot, not just this one.
exit
write                          Saves the running-config (now including the new
                              enable secret and the corrected config-register
                              setting) to NVRAM as the new startup-config, so the
                              recovery is made permanent.

==================================================
STEP 2 - BACK UP THE STARTUP CONFIGURATION TO TFTP1
==================================================

---------------- R1 ----------------

Command                              Result / Explanation
-----------------------------------------------------------------------------------------
ping 192.168.1.100                    Confirms TFTP1 is reachable before attempting
                                      the transfer.
copy startup-config tftp              Initiates a copy of R1's startup-config to a
                                      TFTP server. Prompts for the destination TFTP
                                      server's IP address (192.168.1.100) and a
                                      filename (the default suggested filename was
                                      accepted).

On TFTP1 (Packet Tracer): click TFTP1 -> Services -> TFTP -> confirm
R1's configuration file now appears in the server's file listing,
verifying the backup succeeded.

==================================================
STEP 3 - UPGRADE R1'S IOS IMAGE FROM TFTP1
==================================================

---------------- R1 ----------------

Command                Explanation
-----------------------------------------------------------------------------------------
show version           Displays the currently running IOS image and version — in
                       this lab, a Cisco 2900 series image running version
                       15.1(4)M4, with the exact image filename shown at the
                       bottom of the output.

On TFTP1: browse its file listing to find the newer IOS image also
built for the Cisco 2900 platform — in this lab, version 15.5(3)M —
and copy its exact filename for use in the next command.

---------------- R1 ----------------

Command                                    Explanation
-----------------------------------------------------------------------------------------
copy tftp flash                            Initiates a copy from a TFTP server into
                                           R1's local flash storage. Prompts for the
                                           TFTP server's IP address (192.168.1.100)
                                           and the exact source filename (the newer
                                           IOS image copied from TFTP1's listing).
show flash                                  Confirms flash now contains two IOS
                                           images: the original and the newly copied
                                           one.
delete flash:<old-image-filename>           Deletes the old (now-superseded) IOS
                                           image file from flash, freeing space and
                                           avoiding ambiguity about which image to
                                           boot.
show flash                                  Confirms only the new image remains in
                                           flash.
reload                                      Reboots R1 so it loads using the
                                           (now only) IOS image present in flash —
                                           the newer version.
show version                                After reboot, confirms R1 is now running
                                           the new IOS version (15.5(3)M) and shows
                                           the corresponding new image filename.

==================================================
CONCEPTS LEARNED
==================================================

• ROMMON (ROM Monitor) — a minimal, low-level command environment a
  Cisco device boots into instead of full IOS, entered here via
  Ctrl+Break during boot; it exists independently of any IOS-level
  password and is the standard entry point for password recovery.
• Configuration register — a 16-bit value stored in NVRAM that controls
  various boot behaviors, most relevantly here whether the device loads
  its saved startup-config or ignores it and boots with a blank default
  configuration. Set from ROMMON with `confreg <value>` and from the
  regular CLI with `config-register <value>`.
• 0x2142 vs. 0x2102 — 0x2142 is the specific configuration-register
  value that makes a router ignore NVRAM's startup-config at boot
  (the mechanism password recovery relies on); 0x2102 is the standard
  factory-default value that loads the startup-config normally and must
  be restored after recovery to avoid the device permanently ignoring
  its saved configuration.
• `copy start run` (copy startup-config running-config) — merges the
  saved startup-config into the currently active running-config; used
  in password recovery to bring back the device's real configuration
  after it booted blank, without directly restoring the (still
  password-protected in the file, but now irrelevant since a blank
  config granted access) NVRAM contents another way.
• TFTP (Trivial File Transfer Protocol) — a simple, lightweight file
  transfer protocol (no authentication) commonly used on Cisco devices
  for exactly this kind of task: backing up configuration files and
  transferring IOS images to/from a server, via commands like `copy
  startup-config tftp` and `copy tftp flash`.
• IOS image / flash storage — flash is the router's persistent storage
  holding one or more IOS image files (the operating system itself);
  `show flash` lists what's present, and a device boots from whichever
  valid image flash contains (or a specifically selected one, if
  multiple exist) — `delete flash:<filename>` removes one such image.

==================================================
STUDY NOTES, EXAM SCENARIOS & REAL-WORLD CONTEXT
==================================================

Password recovery via configuration register (0x2142)
  Bypasses a forgotten enable/console password by making the router
  ignore its saved startup-config on the next boot only.
  Exam: memorize 0x2142 (ignore NVRAM config) vs. 0x2102 (default,
  load config normally) — a very frequently tested pair of values, and
  forgetting to restore 0x2102 afterward is exactly the kind of detail
  exam scenario questions probe.
  Real world: this procedure requires physical/console access to the
  device (Ctrl+Break during boot cannot be done remotely in the same
  way), which is precisely why physical security of network equipment
  matters — anyone with console access and a power cycle can bypass a
  forgotten (or even a known-but-undesired) enable password this way.

`copy start run` after a blank boot
  Restores the device's real configuration into running-config after a
  password-recovery blank boot, without ever needing to know the old
  password.
  Exam: know this command specifically follows the config-register
  bypass step in the standard password-recovery sequence — a common
  multi-step exam scenario question sequence.
  Real world: this is also just a generally useful command any time
  running-config drifts from a known-good startup-config and needs to
  be reset without a reload — not exclusive to password recovery.

TFTP for config backup and IOS upgrade
  TFTP has no authentication and transfers in plaintext, but is still
  widely used for these exact tasks in lab and even some production
  environments due to its simplicity.
  Exam: know the direction implied by each `copy` command — `copy
  startup-config tftp` pushes a file from the device to the server,
  `copy tftp flash` pulls a file from the server to the device — mixing
  these up is a common exam trap.
  Real world: config backups to a TFTP/SCP server are a baseline change-
  management practice — before any risky change (like an IOS upgrade),
  the working configuration should already be safely backed up off-box,
  exactly as demonstrated in this lab's ordering (backup happens before
  the upgrade, not after).

IOS upgrade via `copy tftp flash` + `reload`
  Copying a new image into flash does not itself change what the router
  is running — a `reload` is required to actually boot into the new
  image.
  Exam: know that with two images present in flash, the router by
  default boots the image `show flash` lists (or as controlled by the
  `boot system` command, if configured) — deleting the old image here
  is what leaves no ambiguity about which one loads after `reload`.
  Real world: real IOS upgrades follow this same backup-then-upgrade
  pattern, typically also checking free flash space (`show flash`)
  before copying a new image over, since a partially-copied image due to
  insufficient space can leave a device unable to boot at all.
