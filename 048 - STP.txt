LAB NAME

Lab 048 - STP (Spanning Tree Protocol)

==================================================
LAB OBJECTIVE
==================================================

Examine STP (Spanning Tree Protocol) operation on a three-switch
triangle topology (which would otherwise loop broadcasts endlessly
without STP): identify the current STP version/mode, each switch's
bridge ID, the root bridge, interface STP costs, and which port is
blocked and why. Then configure Rapid PVST+ for faster convergence,
manually assign a primary and secondary root bridge per VLAN, and
enable PortFast + BPDU Guard on every access port.

==================================================
TOPOLOGY
==================================================

                        +----------+
                        |   SW2    |   (initial root bridge - lowest MAC,
                        +----+-----+    all default priorities)
                       G0/1 |   | G0/2
                             |   |
              (root port,   |   |   (root port,
               forwarding)  |   |    forwarding)
                             |   |
              +--------------+   +--------------+
              |                                 |
         +----+-----+                     +-----+----+
         |   SW1    |                     |   SW3    |
         +----+-----+                     +-----+----+
             G0/1 -------- BLOCKED -------- G0/2
                    (redundant SW1-SW3 link;
                     SW1's higher bridge ID
                     loses the tie, so SW1's
                     G0/1 blocks to prevent a
                     Layer-2 loop)

    F0/1-F0/3 (each switch)          F0/1-F0/3 (each switch)
   +------+ +------+ +------+       PortFast + BPDU Guard enabled
   |VLAN10| |VLAN20| |VLAN30|       on every PC-facing access port
   +------+ +------+ +------+

SW1, SW2, and SW3 form a physical triangle — every switch has a direct
Gigabit link to both other switches — which is exactly the kind of
redundant Layer-2 topology that would loop a broadcast endlessly
without spanning tree (SW1 to SW2 to SW3 to SW1, forever, in both
directions). VLANs 10, 20, and 30 exist on all three switches, each
running its own independent (per-VLAN) spanning tree instance. Every
switch's F0/1-F0/3 ports face PCs (not shown individually — no specific
PC/IP addressing is used in this lab, it's entirely an STP behavior and
configuration exercise).

==================================================
STEP 1 - EXAMINE THE CURRENT STP STATE (BEFORE ANY CONFIGURATION)
==================================================

---------------- SW1 ----------------

Command                    Result / Explanation
-----------------------------------------------------------------------------------------
enable
show spanning-tree summary   The first line reports "Switch is in pvst mode" — PVST+
                             (Per-VLAN Spanning Tree), meaning each VLAN runs its own
                             independent spanning tree instance, configurable
                             separately. Other STP versions exist (Common Spanning
                             Tree — the original IEEE 802.1D version with one tree
                             for the whole network; Rapid Spanning Tree; Rapid
                             PVST+), but PVST+ is what's running by default here.
                             The output also lists VLAN 1 (default, generally
                             ignored in this lab) plus VLANs 10, 20, and 30.

show spanning-tree            Displays, per VLAN, the root bridge's info and this
                              switch's own bridge ID.
                              - Bridge ID = bridge priority + MAC address. Default
                                priority is 32768; PVST+ adds the VLAN ID to that
                                default per VLAN-instance (e.g. 32768+1=32769 for
                                VLAN 1, 32768+10=32778 for VLAN 10, 32768+20=32788
                                for VLAN 20, 32768+30=32798 for VLAN 30).
                              - The lowest bridge ID becomes the root bridge for
                                that VLAN's spanning tree — priority is compared
                                first, and the MAC address only breaks a tie.
                              - SW1's own bridge ID (shown in the lower section of
                                the output) differs from the root bridge's info
                                (upper section), confirming SW1 is NOT the root
                                bridge for any VLAN yet. SW1's MAC address begins
                                with 00:60 — the numerically highest of the three
                                switches.

---------------- SW2 ----------------

Command                    Result / Explanation
-----------------------------------------------------------------------------------------
enable
show spanning-tree            Same default priorities as SW1 (32769/32778/32788/
                              32798 per VLAN). SW2's MAC address begins with 00:01
                              — the numerically LOWEST of the three switches. Its
                              own bridge ID info and the root bridge info sections
                              are IDENTICAL, and the output explicitly states "This
                              bridge is the root" — confirming SW2 is the root
                              bridge for every VLAN (since all priorities are still
                              equal at this point, the tie is broken purely by
                              lowest MAC address).

---------------- SW3 ----------------

Command                    Result / Explanation
-----------------------------------------------------------------------------------------
enable
show spanning-tree            Same default priorities again. SW3's MAC address
                              begins with 00:04 — in between SW1 (00:60, highest)
                              and SW2 (00:01, lowest). Confirms the full MAC
                              ordering: SW2 (lowest) < SW3 < SW1 (highest), which is
                              exactly why SW2 became root bridge with no
                              configuration needed.

==================================================
STEP 2 - EXAMINE STP INTERFACE COSTS AND THE BLOCKED PORT
==================================================

---------------- SW1 ----------------

Command                    Result / Explanation
-----------------------------------------------------------------------------------------
show spanning-tree            The inter-switch links use Gigabit Ethernet interfaces,
                              which carry a default STP cost of 4. PC-facing links
                              use Fast Ethernet interfaces (which still send/receive
                              spanning tree BPDUs, even though a switch isn't
                              actually connected to that port), carrying a default
                              STP cost of 19 — both values are visible directly in
                              this command's output.

                              The output also shows G0/1 in state "BLK" (blocking) —
                              confirmed visually in Packet Tracer by the port's red
                              status light. Since SW2 is the root bridge, both of
                              its own ports are designated (forwarding) ports. SW1's
                              G0/2 and SW3's G0/2/G0/1 (whichever faces SW2) have the
                              lowest cost path to the root, so they become root
                              ports and forward. That leaves the direct SW1-SW3 link
                              as the one redundant path that must be blocked to
                              prevent a loop — SW1 and SW3 compare bridge IDs on
                              that link, and since SW1's is higher, SW1's G0/1 is
                              the one that blocks (SW3's corresponding port instead
                              becomes a non-root designated/forwarding port on that
                              segment).

==================================================
STEP 3 - CHANGE THE STP MODE TO RAPID PVST+
==================================================

Rapid PVST+ converges much faster after a topology change than classic
PVST+, and should be used whenever the switches support it — a single
command per switch.

---------------- SW1, SW2, SW3 (same command on each) ----------------

Command                            Explanation
-----------------------------------------------------------------------------------------
configure terminal
spanning-tree mode rapid-pvst       Switches from PVST+ to Rapid PVST+ (802.1w-based,
                                    per VLAN) on this switch.

==================================================
STEP 4 - MANUALLY ASSIGN A PRIMARY AND SECONDARY ROOT BRIDGE PER VLAN
==================================================

Rather than leaving root-bridge election to default priorities and MAC
addresses, each VLAN is given an explicit primary root and a specific
backup (secondary) root — standard practice so root bridge placement is
deliberate and predictable rather than accidental.

---------------- Primary roots ----------------

Command                                Explanation
-----------------------------------------------------------------------------------------
SW1: spanning-tree vlan 10 root primary   Makes SW1 the root bridge for VLAN 10.
SW2: spanning-tree vlan 20 root primary   Makes SW2 the root bridge for VLAN 20.
SW3: spanning-tree vlan 30 root primary   Makes SW3 the root bridge for VLAN 30.

`root primary` automatically lowers that switch's bridge priority for
the specified VLAN to a value guaranteed to be lower than every other
switch currently in the topology (rather than requiring a manually
chosen priority number).

---------------- Secondary roots ----------------

Command                                     Explanation
-----------------------------------------------------------------------------------------
SW3: spanning-tree vlan 20 root secondary    Makes SW3 the backup root for VLAN 20
                                             (SW2's VLAN), taking over if SW2 fails.
SW1: spanning-tree vlan 30 root secondary    Makes SW1 the backup root for VLAN 30
                                             (SW3's VLAN).
SW2: spanning-tree vlan 10 root secondary    Makes SW2 the backup root for VLAN 10
                                             (SW1's VLAN).

`root secondary` sets a specific, lower-than-default priority (but
still higher than the primary root's) so that switch takes over as root
only if the primary root becomes unavailable.

---------------- Verify ----------------

Command                    Result
-----------------------------------------------------------------------------------------
show spanning-tree (on SW2) For VLAN 10 (where SW2 is secondary root), the priority
                            is now shown as 28672 + 10 = 28682. For VLAN 20 (where
                            SW2 is primary root), the priority is 24576 + 20 = 24596.
                            (`root primary` typically sets a base priority of 24576,
                            `root secondary` a base of 28672 — both well below the
                            default 32768 — with the VLAN ID still added on top.)

==================================================
STEP 5 - ENABLE PORTFAST AND BPDU GUARD ON ACCESS PORTS
==================================================

PortFast and BPDU Guard should only be enabled on ports that connect to
end hosts (PCs), never on ports connecting to other switches.

- **PortFast** lets an access port skip straight to the forwarding
  state, without waiting through STP's normal listening/learning delay
  — appropriate because a PC doesn't participate in a Layer-2 loop the
  way a switch does.
- **BPDU Guard** puts a port into err-disabled state immediately if it
  ever receives a BPDU (Bridge Protocol Data Unit) — protecting against
  someone plugging an unauthorized switch (or a device generating STP
  BPDUs) into what should be a simple end-host port.

A global command — `spanning-tree portfast default` — can enable
PortFast on every access port at once; this lab instead configures it
per-interface for the specific ports in use.

---------------- SW3, then SW1, then SW2 (same commands on each) ----------------

Command                                Explanation
-----------------------------------------------------------------------------------------
configure terminal
interface range FastEthernet0/1-3       The three PC-facing access ports on this
                                        switch.
 spanning-tree portfast                 Enables PortFast on these ports.
 spanning-tree bpduguard enable         Enables BPDU Guard on these ports.

==================================================
CONCEPTS LEARNED
==================================================

• STP (Spanning Tree Protocol) — a Layer 2 protocol that prevents
  broadcast/switching loops in a network with redundant physical links
  between switches, by logically blocking just enough ports to leave
  exactly one active path between any two switches, while keeping the
  redundant links available as backups if the active path fails.
• PVST+ (Per-VLAN Spanning Tree) vs. Rapid PVST+ — PVST+ runs one
  independent instance of (classic 802.1D-based) spanning tree per
  VLAN; Rapid PVST+ runs one instance per VLAN too, but uses the faster
  802.1w Rapid STP algorithm underneath, converging much faster after a
  topology change.
• Bridge ID — the value used to elect a VLAN's root bridge, made up of
  a bridge priority (default 32768, with the VLAN ID added in PVST+/
  Rapid PVST+) plus the switch's MAC address as a tiebreaker; the
  lowest bridge ID overall wins the root bridge election for that VLAN.
• STP port roles — root port (the port with the lowest-cost path back
  to the root bridge, always forwarding, exactly one per non-root
  switch), designated port (the forwarding port on a given network
  segment, always true for the root bridge's own ports), and blocking
  port (not forwarding, kept ready as backup) — assigned to whichever
  port loses the cost/bridge-ID comparison on a redundant segment.
• `spanning-tree vlan <id> root primary` / `root secondary` — commands
  that lower a switch's bridge priority for a specific VLAN low enough
  to guarantee it becomes root (`primary`) or the designated backup root
  (`secondary`), without requiring the administrator to calculate and
  set an exact priority number manually.
• PortFast — skips the normal STP listening/learning delay on a port,
  letting it go straight to forwarding; intended only for ports facing
  end hosts, since a host doesn't create switching loops the way
  another switch would.
• BPDU Guard — immediately error-disables a port if it receives a BPDU,
  protecting PortFast-enabled, end-host-facing ports from someone
  connecting an unauthorized switch (which could otherwise participate
  in — and potentially disrupt — the spanning tree).

==================================================
STUDY NOTES, EXAM SCENARIOS & REAL-WORLD CONTEXT
==================================================

Bridge ID and accidental root bridge election
  With all priorities equal, the lowest MAC address wins root bridge
  election — which is essentially random from a design perspective.
  Exam: know the exact bridge ID formula (priority + VLAN ID for PVST+/
  Rapid PVST+, then MAC address as tiebreaker) and that default
  priority is 32768 — a very frequently tested number.
  Real world: leaving root bridge election to chance (default
  priorities) is a real anti-pattern — an old access-layer switch could
  accidentally become the root bridge for the whole network purely by
  having the lowest MAC address, creating a bottleneck or single point
  of failure exactly where you don't want one. This is precisely why
  Step 4 of this lab (deliberately setting root primary/secondary) is
  standard real-world practice, not just an exam exercise.

Gigabit (cost 4) vs. Fast Ethernet (cost 19) STP costs
  Lower cost is preferred — a lower-cost path to the root wins the
  root-port election.
  Exam: memorize the default STP port cost table (10 Mbps=100,
  100 Mbps=19, 1 Gbps=4, 10 Gbps=2) — this lab only exercises two of
  those values but the full table is testable.
  Real world: STP cost is one of the levers (along with bridge
  priority) used to deliberately engineer which physical links carry
  traffic and which stay in standby — e.g. preferring a fiber uplink
  over a slower backup copper link between two switches.

PortFast + BPDU Guard, applied only to access ports
  PortFast skips STP delay states; BPDU Guard protects that port from
  unauthorized switches.
  Exam: know these are meant for end-host ports ONLY — enabling PortFast
  on a port that actually connects to another switch (even
  accidentally) risks a temporary loop, since that port skips the
  loop-prevention delay entirely.
  Real world: BPDU Guard is a real security control against "rogue
  switch" incidents — an employee plugging a cheap unmanaged switch (or
  a misconfigured device) into a wall jack that's wired to a
  PortFast+BPDU-Guard port gets that port automatically shut down the
  instant a BPDU appears, rather than silently joining (and possibly
  destabilizing) the production spanning tree.
